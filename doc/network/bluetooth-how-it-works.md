打开一副新耳机，手机很快就能找到它；点击连接后，音乐便从耳机中播放出来。这个过程不需要网线，也不需要接入互联网，但手机和耳机仍要完成一系列沟通：发现对方、建立连接、确认身份、了解对方支持的功能，最后才开始传输声音。

这篇文章就从这条过程出发，聊聊蓝牙是怎样让两台设备隔空通信的。同样的原理也适用于键盘、手环、音箱和其他蓝牙设备。

## 一次蓝牙连接，背后发生了什么

一次典型的蓝牙连接，大致可以分为下面几步：

```mermaid
flowchart LR
    A[发送无线信号] --> B[发现附近设备]
    B --> C[建立连接]
    C --> D[确认设备身份]
    D --> E[确认支持的功能]
    E --> F[传输声音或其他数据]
    F --> G[保持或恢复连接]
```

| 步骤 | 需要解决的问题 |
| --- | --- |
| 发送无线信号 | 数据怎样穿过空气到达另一台设备 |
| 发现附近设备 | 两台陌生设备怎样知道对方存在 |
| 建立连接 | 双方怎样约定接下来的通信方式 |
| 确认设备身份 | 怎样避免连接到错误或不可信的设备 |
| 确认支持的功能 | 怎样知道对方能播放声音还是提供其他数据 |
| 传输数据 | 声音、按键和心率数据怎样正确到达 |
| 保持或恢复连接 | 怎样减少耗电，并在断开后重新连接 |

这并非所有蓝牙设备都必须严格走完的固定流程。有些设备只向周围广播少量信息，根本不需要别人连接它；已经配对过的设备再次连接时，也跳过了确认数字那一步。但手机第一次连接一副新耳机、一把新键盘或一个手环时，通常会经历其中大部分步骤。

蓝牙也不是只有一种工作方式。日常设备用的主要是经典蓝牙和低功耗蓝牙两种。前者在耳机和音箱上用了很多年，后者常见于手环、传感器这些得靠电池撑很久的小设备。现在也有耳机开始用低功耗蓝牙来传声音了。两种蓝牙的内部规则不一样，但对使用者来说，它们都得解决上面这几个基本问题。

## 蓝牙如何隔空传输数据

手机里的音乐、键盘敲出来的按键和手环记录的心率，原本都是设备内部的数据。发送的时候，蓝牙芯片先把数据切成适合无线传输的小块，再让天线把它们变成在空中变化的无线电波发出去。另一台设备的天线收到这些信号，再还原成原来的数据。

蓝牙工作在 2.4 GHz 这个公共频段上。你可以把"频段"理解成一块大家共享的无线电频率区间。这个频段在大多数国家和地区都是开放的，所以蓝牙设备拿到不同地方都能用。麻烦的是，Wi-Fi、其他蓝牙设备、还有一些无线外设也挤在这条路上，多台设备很可能同时在同一片空气里发送信号。

为了减少互相干扰，蓝牙把可用频段分成多个较窄的信道，并在通信过程中不断切换信道。如果某个信道刚好受到 Wi-Fi 或其他设备干扰，后续数据可以换到另一个信道发送。有些设备还会记录哪些信道近期表现较差，并尽量减少使用它们。

切换信道只能降低持续受干扰的概率，不能让干扰完全消失。当附近无线设备过多、信号被严重遮挡，或者两台设备距离过远时，接收方仍可能无法正确还原数据。

墙壁、家具和人体也会削弱或反射无线信号。把手机放在裤子口袋里时，人体可能正好位于手机与耳机之间；即使两者相距不远，连接质量也可能低于手机放在桌面上的情况。

## 手机是怎么发现耳机的

一副新耳机进入可发现状态后，会周期性地广播一些很短的无线消息，相当于朝周围喊："这里有个设备，我叫某某，现在可以连我。"你打开手机蓝牙列表的时候，手机就在到处听这些消息，把听到的设备一个个列出来。

发送和监听并不会一直刚好对上。耳机隔一阵子喊一声，手机也按自己的节奏听。如果两者的时机还没碰上，列表就得等几秒才能更新。耳机降低广播频率可以省电，但代价就是手机可能更晚才能发现它。

设备还必须处于"愿意被看见"的状态。很多耳机只在首次开机或者长按配对键之后才会进入这个状态，过一阵子又会自动退掉。退出之后，耳机可能还惦记着以前连过的手机，会悄悄尝试找它，但不会再出现在其他手机的搜索结果里。

经典蓝牙和低功耗蓝牙广播"我在这里"消息的具体方式不一样，手机在系统内部帮你处理了这些差异。对使用者来说，关键是区分两个概念：在列表里看到耳机只说明你发现了它，不等于你们已经连上了。

设备列表里显示的名称也不是靠谱的唯一身份。同一型号的耳机多拿几副出来，可能都叫一个名字，而且名字还能改。蓝牙本身用其他更底层的设备信息来识别通信对象，手机界面只是把它翻译成你好认的文字。

## 找到设备后，它们怎样连起来

你点击设备名称之后，手机会向那个设备发出连接请求。只要对方还在附近、允许被连，而且没有因为自身限制拒绝请求，两边就开始搭建通信通道了。

搭通道的时候，两台设备会约好接下来什么时候收发数据、用哪些信道。它们没必要一直亮着无线信号，只需要在约定的时间点醒过来，跳到同一个信道上交换数据就行。这样既能维持连接，又不用让无线芯片一直跑着。

如果一方暂时没有收到消息，连接不会立即断开，因为数据可能只是受到短暂干扰。只有经过一段时间仍然无法成功通信，设备才会认为对方已经离开或不可用，并结束连接。

界面上显示的"已连接"，只说明两台设备之间有一条可用的通信通道。它既不代表身份已经充分确认，也不保证双方支持同样的声音、按键或数据功能——这些问题得靠后面的步骤来解决。

## 配对时，为什么要你确认那组数字

第一次连某些设备的时候，手机会弹出一组数字，让你看看另一台设备上是不是显示同样的数字。这一步属于配对，目的不是让信号变强，而是帮两台设备建立一条彼此信任的安全通道。

确认数字一致，能降低你连到了别人设备、或者中间有人冒充的风险。键盘这类带输入能力的设备，还可能要求你直接输入一组数字。耳机没有屏幕也没有完整键盘，只好走更简单、不需要用户确认数字的流程——操作方便了，但身份确认的强度也随之降低。

配对过程中，两台设备会生成一份只有他们俩知道的安全信息。之后传出去的数据就可以被加密，也就是说，即使别人截到了信号，也看不懂里面是什么。不过加密管的是通信内容；对方到底是不是你以为的那个设备，还得看配对时用的是什么确认方式。

配对成功后，设备一般会保存这份安全信息——可以理解为"记住"了对方。下次再连的时候，两边直接用保存的凭证确认彼此，不用再弹数字让你对了。

你把配对记录删了，相应的安全信息也就没了。就算另一台设备还留着旧记录，两边的状态已经对不上，通常需要两边都清除旧记录再重新配对。

不过并不是所有数据都要求先配对。有些设备可以公开发送温度、位置提示这类不敏感的信息；一旦涉及私人数据或者设备操控，产品一般都会要求先建立更严格的安全关系。

## 已经连接，为什么还不能马上使用

建立连接只表示两台设备可以互相传数据，但你得知道这些数据到底是什么意思。耳机要收的是声音和播放控制指令，键盘要发的是按键，手环要往外报心率、步数和电量。它们组织数据的方式各不相同。

蓝牙给常见功能定了一套两方都能看懂的规则。比如，有一条规则约定了耳机怎样接收声音、手机怎样发暂停命令；另一条规则约定了键盘怎么表示某一个按键。两边只有支持同一套规则，对应的功能才能跑起来。

一般低功耗设备还会把自己能提供的东西整理成一项项"服务"。服务可以理解成设备向外公布的一类功能，比如心率测量、电量信息。手机连上手环之后，会先翻一遍它挂了哪些服务，再按约定的方式去读数据或者收更新。

所以你可能会碰到这样的情况：设备明明显示连接成功，某个功能就是不能正常使用。可能是手机不认识对方提供的功能，可能是两边支持的声音传输方式不一样，也可能是这个功能要求先完成更严格的安全确认。

## 声音、按键和心率是怎样传过去的

确认双方支持的功能后，数据大致经过以下过程：

1. 手机、键盘或手环产生需要发送的数据；
2. 数据按照对应功能的规则整理，再拆成适合无线传输的小块；
3. 每一块附带必要的识别和检查信息；
4. 蓝牙芯片在约定的时间和信道上发送这些小块；
5. 接收方检查数据没坏之后，把相关内容拼回去；
6. 完整数据交给声音播放、按键处理或健康应用。

把数据拆小，一方面避免一次传输占着信道太久，另一方面哪一块出问题了也容易发现。附带的那点检查信息，则告诉接收方：这堆数据属于哪条连接、路上有没有出错、应该交给哪个功能模块去处理。

不同数据对传输的要求不太一样。按键和控制命令讲究完整送达，丢了可以重发。音乐和通话更在乎的是数据能不能及时到：一小段声音错过了播放时间点，后面补到了也没什么用。所以声音传输会在及时性和完整性之间做取舍——宁可偶尔丢掉一小块，也不能等。

这也是蓝牙受到干扰时表现不一样的原因——键盘可能只是偶尔顿一下，文件或传感器数据可以耐心重传，耳机则可能直接出现一瞬间的声音中断。

## 蓝牙一直开着，为什么不太耗电

无线设备主要是在发送和接收信号的时候耗电。如果一直监听或者持续往外发，电量很快就没了。蓝牙省电的核心思路很简单：只在需要的时候短暂干一下活，其他时间尽量让无线部分休息。

拿手环来说，它可以隔一段时间醒过来一次，把新数据塞给手机，完事继续睡。手机界面可能还是显示"已连接"，因为两边保留着连接需要的信息，并且都知道下一次该在什么时候出来见面。

耳机播放音乐时需要持续接收大量声音数据，无法像手环一样长时间休息，所以耗电通常更快。即便如此，它也可以在没有声音、暂停播放或放回充电盒后减少无线活动。

省电和使用体验之间永远在打架。设备查消息越勤快，响应越快，但醒来的次数也越多；少查几次能撑更久，代价是发现设备或传数据时你可能要多等一会儿。"蓝牙已开启"或"设备已连接"这几个字本身不能告诉你实际耗电——关键看设备多久干一次活、每次传多少数据。

## 走远断开后，为什么回来又能自动连上

保持连接时，两台设备按约定好的时间交换消息。偶尔漏掉几次，可能是无线干扰，设备一般会继续尝试。如果隔了很久还是收不到对方的回应，连接就被视为断开了。

走远、关闭设备、进入信号较差的房间，或者让耳机连接到另一台手机，都可能导致原有连接结束。断开的是当前无线通道，不一定会删除此前保存的配对信息。

重新靠近之后，其中一台设备可以再次搜索，或者直接尝试连接熟悉的设备。只要两边还保存着匹配的安全信息，就能确认老伙计没错，恢复受保护的通信。这个过程系统可以自动搞定，所以在你的视角里就是"走远了断了，回来自己又连上了"。

自动重连不意味着原来的连接一直没断。设备实际上重新搭了一条无线通道，只是帮你省掉了再次选设备和确认数字的步骤。配对信息如果被删了，或者耳机这会儿正连着另一台不让同时用的设备，自动重连就可能失败。

## 常见现象背后的原因

### 靠得很近，为什么仍然搜索不到设备

距离近只说明信号条件好。目标设备还得处于可被发现的状态，并且它喊的时候你正好在听。它可能已经连上了另一台手机，或者被操作系统按权限和设备类型过滤掉了。

### 已经连接，为什么还是不能用

连接搭好了只是有路可走。两边还得支持同样的功能和数据规则，有些功能还得先走完配对或加密的流程。比如手机能跟设备建立基础连接，不代表双方一定支持同一种声音传输方式。

### 人多时，为什么蓝牙音频容易卡顿

人多的场合通常 Wi-Fi 和蓝牙设备也多，大家共享的 2.4 GHz 频段更挤了。人体还会遮挡、吸收一部分信号。切换信道和重发能缓解一些，但声音数据要是没及时到，卡顿还是免不了。

### 删除配对记录后，为什么无法自动连接

配对记录里存着识别身份和保护通信所需的信息。删掉之后，两边的安全关系没法恢复。一边删了而另一边还留着旧记录，通常得两边都清干净再重新配对。

### 显示已连接，为什么仍然可以很省电

已连接不等于一直在发信号。手环这类设备可以只在约定的时间点短暂醒来，换完那点数据就继续休息。实际耗电取决于干活有多勤、每次传多少数据，以及用多大功率往外发。

### 蓝牙到底能连接多远

Bluetooth SIG 给出的整体范围跨度是不到 1 米到超过 1 千米。这不是说普通耳机可以连接一千米，而是说明不同蓝牙产品的设计目标和使用环境差别很大。

下面的距离是常见条件下的量级参考，不是蓝牙规范或厂商对具体设备的保证：

| 使用条件 | 大致连接距离 | 主要限制 |
| --- | --- | --- |
| 耳机、手环等小型设备，隔着人体或处于拥挤室内 | 约 1～5 米 | 人体遮挡、设备体积和无线干扰 |
| 手机与耳机、键盘等普通设备，在同一房间且遮挡较少 | 约 5～10 米 | 墙壁、人体移动和设备摆放方向 |
| 普通设备处于开阔室内或室外无遮挡环境 | 约 10～30 米 | 两端设备的发送和接收能力 |
| 专门提高发送功率并优化天线的设备，处于无遮挡环境 | 约 50～100 米，部分设备可以更远 | 功耗、设备天线和当地法规 |
| 专门为远距离设计的低速蓝牙设备 | 数百米，理想条件下可以超过 1 千米 | 需要两端支持，并以更低的数据传输速度换取距离 |

这些区间彼此会有重叠。同一副耳机，在空旷房间也许能跑到十几米开外，但在人体遮挡和无线设备扎堆的地方，几米内就可能开始卡。产品标称的连接距离只能在对应的测试条件下理解，不能直接套到所有设备和环境上。

蓝牙连接并不是一次简单的信号发送。它要先把设备互相发现，再搭通信通道、建立安全关系，接着确认双方能理解的功能，最后才真正开始传输声音或其他数据。把连接时机、传输内容和休息时间安排妥当之后，设备才能在通信距离、稳定性、响应速度和续航之间找到一个平衡。
