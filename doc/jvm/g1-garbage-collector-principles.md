# G1 垃圾回收器原理与实现方式

G1 的全称是 Garbage-First Garbage Collector。它最核心的目标，不是把 GC 做得“绝对最快”，而是让停顿时间更容易控制，尤其是在堆比较大的服务端场景里。

如果只先记一条主线，可以把 G1 理解成下面这句话：

- G1 先把堆拆成很多小块。
- 再找出哪些小块垃圾最多。
- 然后优先回收“最划算”的那一批小块。

所以，G1 的本质不是单纯的分代回收，而是下面四种机制的组合：

- 分区回收。
- 并发标记。
- 复制整理。
- 停顿预算控制。

## 一、先看结论：G1 到底比传统 GC 多做了什么

传统分代收集器更像是在处理“整片区域”：

- 年轻代满了，就收年轻代。
- 老年代压力大了，就尽量处理老年代。

这样做的问题是，堆一旦变大，老年代回收就容易变重，停顿时间也更难预测。

G1 的思路换了一下。它不把老年代看成一整块，而是看成很多小块中的一部分。这样 JVM 就可以在一次回收里只处理最值得回收的若干块，而不是每次都碰整个老年代。

换句话说，G1 解决的核心问题是：

- 如何把大堆回收拆成很多次较小的回收。
- 如何在有限停顿时间里，优先回收收益最高的区域。
- 如何在分批回收的同时，尽量不留下严重碎片。

## 二、先认识 4 个最重要的概念

如果一开始就陷进各种术语，G1 会显得很绕。先抓住下面 4 个词，后面的流程就容易很多。

### 1. Region：堆里的“小方格”

G1 会把整个 Java 堆切成很多大小相同的 Region。可以把它想成把一大片仓库地面切成很多同样大小的方格。

每个 Region 在某个时间点会扮演一种角色：

- Eden：新对象主要分配在这里。
- Survivor：Young GC 后还活着的年轻对象会先放这里。
- Old：存活时间更久的对象放这里。
- Humongous：超大对象单独走特殊通道。
- Free：空闲 Region，可以重新分配用途。

最关键的一点是：

- 年轻代和老年代在 G1 里是逻辑分组，不是固定地址区间。

也就是说，一个 Region 这次是 Eden，下次完全可能变成 Old 或 Free。

### 2. Collection Set：本轮真正要回收的那一批 Region

每次 GC 时，G1 都不会默认处理整个堆，而是先挑出“这次要回收的 Region 集合”，这个集合就叫 Collection Set，简称 CSet。

你可以把它理解成：

- G1 每一轮只拿一部分方格出来清理。

这也是 G1 能把一次大回收拆成很多小回收的关键。

### 3. Remembered Set：记录“外面谁可能指向我”

如果只回收某几个 Region，就一定会遇到一个问题：

- 我准备清理 A 区域，但别的区域会不会还有对象指着 A 里面的对象？

G1 的做法是给每个 Region 准备一份 Remembered Set，简称 RSet。它记录的不是“所有引用关系”，而是更实用的一件事：

- 哪些外部区域，可能有引用指向当前 Region。

这样回收某个 Region 时，就不用把整个堆全部扫描一遍，只需要扫描：

- 这个 Region 自己。
- 以及 RSet 提示出来的那些外部位置。

### 4. 并发标记：先摸清垃圾分布，再决定优先回收谁

G1 之所以叫 Garbage-First，是因为它不会盲目回收，而是会先统计：

- 哪些 Region 里活对象多。
- 哪些 Region 里垃圾比例高。

这个统计过程主要靠并发标记完成。只有先知道“哪里垃圾最多”，后面才能谈“优先回收最值的一批”。

## 三、G1 平时是怎么运行的

先不要急着看 GC 细节，先看应用程序运行时，G1 平时在做什么。

### 1. 新对象先进入年轻代 Region

大多数普通对象会先分配到 Eden Region。应用线程通常通过 TLAB 在本地快速分配，所以正常情况下，G1 不会让每次 new 对象都变得很慢。

### 2. 对象存活下来，就被复制到别的 Region

当 Young GC 发生时，还活着的对象不会在原地整理，而是被复制走：

- 先尽量复制到 Survivor Region。
- 达到晋升条件后，再复制到 Old Region。

这件事很重要，因为它意味着：

- G1 的整理动作是顺手完成的。

只要活对象都被搬走，原来的 Region 就可以整块清空，不容易留下严重碎片。

### 3. G1 一边运行，一边维护“跨 Region 引用”信息

对象引用在程序运行时一直会变化。比如一个老年代对象可能突然指向一个年轻代对象，或者一个对象字段被改成了另一个引用。

如果这些变化完全不记录，GC 时就只能重新扫描整个堆，停顿时间会非常难看。

所以 G1 会借助写屏障，把这些引用变化记录下来，后面再整理进 RSet。

## 四、为什么 G1 能只回收一部分堆

这部分是 G1 最关键的实现思想。

假设 JVM 准备回收几个 Region。如果它不知道其他 Region 有没有引用这些区域里的对象，那它为了安全就只能扫全堆。这样一来，“分区回收”就失去了意义。

G1 为了解决这个问题，做了两层设计。

### 1. 用 card table 把引用变化先粗略记下来

HotSpot 不会精确到“每改一次引用都立刻维护一张完整引用图”，那样太贵。它的做法更像是：

- 先把堆切成很多更小的 card。
- 某个 card 上一旦发生引用写入，就先把这张 card 标记为脏。

这一步的目标很简单：

- 先快速记住“这里可能有跨 Region 引用变化”。

### 2. 再把脏 card 精化成 Remembered Set

后面 refinement 线程或者 GC 线程会去处理这些脏 card：

- 扫描 card 上的引用。
- 判断哪些引用真的跨了 Region。
- 把结果更新到目标 Region 的 RSet。

所以 RSet 不是每次写引用都同步精确更新，而是：

- 先粗记。
- 再异步精化。

这样做的好处是，应用线程的写入成本不会太重，但 GC 需要的信息又能逐步补齐。

## 五、写屏障到底在帮 G1 做什么

很多人第一次看到写屏障会觉得抽象。其实对 G1 来说，可以把它理解成“程序写引用时顺手打一个日志”。

G1 主要依赖两类写屏障。

### 1. 后写屏障：服务于 Remembered Set

当代码执行类似下面这种引用赋值时：

```java
obj.field = newRef;
```

G1 会在写入之后做一件额外的事：

- 记录这次写入所在的 card 可能变脏了。

它不是立刻就把所有跨 Region 关系精确算出来，而是先留下线索，后续再异步处理。

所以后写屏障的作用可以直接记成一句话：

- 它帮助 G1 维护 RSet。

### 2. 前写屏障：服务于并发标记

G1 的并发标记使用 SATB，也就是 Snapshot-At-The-Beginning。这个名字可以翻译成一句更容易懂的话：

- 标记时，我想尽量保住“标记开始那一刻”的对象可达关系。

问题在于，标记线程工作时，用户线程并没有停下来。比如原来 A 引用着 B，结果标记还没来得及看到这条边，用户线程就把它断开了。

如果什么都不做，B 就可能被漏标。

G1 的办法是：

- 在引用被覆盖之前，先把旧引用值记下来。

这个动作由前写屏障完成，旧引用会被放进 SATB buffer，后面的并发标记线程再去处理。

所以前写屏障可以简单记成：

- 它帮助 G1 在并发标记时别漏对象。

## 六、Young GC：G1 最常见的一次回收是怎么做的

G1 最常发生的并不是 Mixed GC，而是 Young GC。

一次 Young GC 可以按下面的顺序理解：

1. 暂停应用线程。
2. 选出本轮要回收的年轻代 Region，组成 CSet。
3. 从 GC Roots 和相关 RSet 出发，找出还活着的对象。
4. 把这些存活对象复制到新的 Survivor Region 或 Old Region。
5. 修正引用。
6. 原来被回收的 Region 整块变成 Free Region。
7. 恢复应用线程。

这里有两个很值得记住的点。

### 1. G1 回收时顺便完成压缩

它不是在原地挪一挪对象，而是直接把活对象搬走。这样原区域就能整体清空，因此 G1 在正常回收路径里天然带有整理能力。

### 2. 停顿时间主要花在“找活对象”和“复制活对象”上

所以某次 Young GC 快不快，往往取决于：

- 要扫描多少引用。
- 要复制多少存活对象。

这也解释了为什么“垃圾多”不一定更慢，很多时候真正贵的是“活对象多”。

## 七、并发标记：G1 如何知道哪些老年代 Region 最值得回收

Young GC 只能高频处理年轻代。要想分批处理老年代，G1 还得回答一个问题：

- 老年代里，哪几个 Region 的垃圾最多？

这个答案来自并发标记周期。

### 1. Initial Mark

这是一次很短的停顿，通常会和某次 Young GC 一起做。它的目标是先把根对象相关的起点记下来。

同时，G1 还会记录 TAMS，也就是 Top-at-Mark-Start。可以把它理解成：

- 这是本轮标记开始时，每个 Region 的一个分界线。

标记开始之后新分配出来的对象，不需要再按“旧快照里的老对象”那样重新追一遍。

### 2. Concurrent Mark

这是并发阶段。GC 线程和应用线程同时工作。

它会做的事是：

- 从已知根对象出发遍历对象图。
- 结合 SATB buffer，把并发期间被用户线程改掉的旧引用补回来。
- 统计每个 Region 还剩多少活对象。

这一步最重要的产出不是“哪些对象活着”，而是：

- 每个 Region 的存活量。
- 每个 Region 的垃圾比例。

### 3. Remark

这是并发标记结束前的一次关键停顿，用来做最后收尾：

- 处理剩余 SATB buffer。
- 补齐最后的标记工作。
- 收敛一些必须停顿处理的引用相关逻辑。

### 4. Cleanup

Cleanup 会根据标记结果更新 Region 级别的统计，识别完全空的 Region，并整理出后续 Mixed GC 的候选区域。

到这里，G1 才真正拥有了“垃圾地图”。

## 八、Mixed GC：为什么它叫 Garbage-First

并发标记完成后，G1 不会马上做一次“整老年代回收”。它通常会进入一段 Mixed GC 周期。

Mixed GC 的意思是：

- 这次回收不只收年轻代。
- 还会顺带收一部分老年代 Region。

关键点在于，老年代 Region 不是随便选的，而是优先挑那些：

- 垃圾比例高。
- 回收收益大。
- 扫描和复制成本又没有高到超出本轮停顿预算。

这就是 Garbage-First 的真正含义：

- 不是先收“某一代”。
- 而是先收“最值得收的那批 Region”。

## 九、G1 为什么能把停顿时间控制得更稳一些

G1 经常和这个参数一起出现：

```text
-XX:MaxGCPauseMillis=200
```

这个参数表达的不是硬性承诺，而更像一个目标：

- 我希望单次 GC 停顿尽量控制在这个量级附近。

G1 会基于历史统计去估算：

- 扫描 RSet 大概要花多久。
- 复制这些活对象大概要花多久。
- 处理引用更新大概要花多久。

然后它再决定：

- 本轮 CSet 最多应该装多少 Region。

所以 G1 的“可预测停顿”本质上不是魔法，而是一套预算模型。它做的不是保证每次都一样短，而是尽量避免某次突然收得特别重。

## 十、Humongous Object：G1 最容易让人忽略的一条特殊路径

当对象大到超过一个 Region 容量的一半时，G1 通常会把它当作 Humongous Object 处理。

这类对象不会走普通对象那条“年轻代里复制多次再晋升”的路，而是直接占用一个或多个连续 Region。

这样做的好处是：

- 避免反复复制超大对象。

但代价也很明显：

- 需要连续 Region。
- 更容易受碎片影响。
- 分配和回收跟不上时，更容易把堆占用顶高。

所以在 G1 场景里，超大对象往往是性能分析里必须单独盯的一类问题。

## 十一、什么时候 G1 会表现变差

G1 不是不会出问题，它只是把很多问题变成了“更晚出现”或者“更容易控制”。如果下面几种情况同时加重，停顿表现还是会恶化：

- 老年代增长太快，并发标记来不及完成。
- 存活对象太多，复制成本明显升高。
- Humongous 对象太多，连续 Region 紧张。
- RSet 维护成本太高，屏障和 refinement 开销变重。
- Evacuation 时备用空间不够，复制过程容易失败。

所以看 G1 日志时，不能只盯“收了多少垃圾”，还要盯：

- 活对象比例高不高。
- 老年代回收是否跟得上分配速度。
- Humongous 分配是否频繁。

## 十二、几个最常见参数，分别在控制什么

### 1. MaxGCPauseMillis

控制目标停顿时间。它会影响 G1 挑选 CSet 的策略，但不是严格 SLA。

### 2. InitiatingHeapOccupancyPercent

控制并发标记大致在堆占用达到什么水平时开始。如果设得太晚，老年代可能已经很紧了，标记还没跑完。

### 3. G1HeapRegionSize

控制 Region 粒度。Region 太大，回收就不够细；Region 太小，RSet 和元数据开销会更明显。

### 4. G1ReservePercent

控制保留多少额外空间给 evacuation 使用。它本质上是在给对象复制阶段留余量，避免目标空间太容易不够。

## 十三、用一条完整主线把 G1 串起来

如果把前面的内容压缩成一条最容易记忆的流程，可以这样看：

1. G1 先把堆切成很多 Region。
2. 平时靠写屏障持续记录引用变化，维护 RSet 和并发标记所需的信息。
3. 年轻代满了，就做 Young GC，把活对象复制走，顺带完成整理。
4. 后台并发标记统计每个老年代 Region 的垃圾比例。
5. Mixed GC 再从这些 Region 里挑出最值得回收、且本轮停顿装得下的一批做回收。
6. 整个过程反复循环，于是大堆也能被拆成很多次较小、较可控的回收。

## 总结

G1 最值得抓住的，不是某一个术语，而是它背后的整体思路：

- 它把堆拆小了，所以回收可以分批做。
- 它提前维护跨 Region 引用，所以局部回收时不用每次扫全堆。
- 它先并发统计垃圾分布，所以能优先回收最划算的 Region。
- 它通过复制回收顺手整理内存，所以碎片问题比纯标记清除更容易控制。
- 它再用停顿预算去约束每次回收的工作量，所以停顿表现通常比传统整代回收更稳。

因此，G1 的本质可以用一句更通俗的话概括：

- 它不是一次性把整间仓库打扫干净，而是先看哪几块地方最脏、最好收拾，再在每次可接受的时间里优先清理那几块。
