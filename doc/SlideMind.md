自己vb coding用ai写了一个可以生成ppt的工具，主要是给不理解ai的人使用，降低门槛，自己会使用agent工具的请绕行，或者看看原理笑笑得了。

## 主要功能
1. 支持提取 DOC、DOCX、XLS、XLSX、PDF 文本、PPTX（只读提取，不保证无损）
2. agent可以联网搜索、下载
3. 文档修改历史记录，不管是人还是agent在应用里改文档均会保存历史记录，支持回滚，外部程序改文件只会刷新界面，不进历史记录
4. 通过skill实现可修改ppt的产出（应用内为结构化json），支持导出可修改ppt，因为使用的是三方库，具体支持程度得看大哥们了
5. 权限限制只能读写选定工作区的文件，网络工具可以搜索，下载功能是受限的，只能下公开https的图片和utf-8文本，而且这一层限制的是模型能调用哪些工具，不是操作系统沙箱，挡不住本机的其他进程

## 支持模型
理论上支持所有pi接入的所有厂商，但是因为DeepSeek便宜，目前只接入了DeepSeek，默认是DeepSeek V4.1 Flash，另外还有一个V4 Pro


## 链路
项目中通过注入Prompt和skill，以下面的工作流驱动，但是能否按照约束执行需要看接入模型的指令遵循度，目前使用DeepSeek是感觉没问题的。

```mermaid
flowchart LR
    A["整理材料"] --> B["确定大纲"]
    B --> C["逐页文案"]
    C --> D["视觉与模板"]
    D --> E["生成可编辑稿"]
    E --> F["检查与修改"]
    F --> G["按需导出"]
```

## 设计思路

### 关于ppt生成目前主流的方案有
1. 直接操作本机Office或者是通过mcp桥接，因为网络或者是需要做额外安装插件，再加上实现相对更加困难，在设计的时候没有考虑
2. 生成网页，再次导出为ppt，这种之前也尝试过，绝大部分路线导出结果都是图片，并且如果是网页的话，基本失去了人工可以修改的可能
3. 生成结构化数据，再次导出为ppt，这个是本项目选取的方案，选的原因很简单，结构化的数据ai理解起来方便，实现也简单，缺点就是动画和特殊图形的支持并不完善，导出结果可能和预览不一致

### 关于agent的选择
这个在刚开始做的时候刚好dsh出来了，就想着做一个dsh的插件，在尝试过之后发现dsh并不自由，我想近乎完全屏蔽和技术相关的内容，最后的是选择了pi。

应用负责注入工具、插件、prompt、做权限管理、密钥的保存，pi负责所有和模型api的交互。

### 各种插件
#### ppt读写修改生成
使用了PPTist，感谢大佬的开源，但是屏蔽了这个项目中和ai相关的内容，保留了修改、导出等核心功能，本项目和ppt相关的能力全部依赖于这个库。

另外还尝试了Univer Pro，但是因为许可证的问题，放弃了。

#### 文件读写
依赖Apache Tika，实际上在启动应用的时候还会顺带使用自带的jre启动一个Tika的后台Java进程，没有权限校验，本机进程完全可以访问，不过这个服务只监听127.0.0.1，局域网是访问不到的，但是因为没啥数据隐私问题，无所谓了

#### 注入pi的插件
最开始选择了下面的插件：
- pi-continue：长任务的中途续接与安全压缩
- pi-free：在 Pi 的模型选择器中注册免费和付费的 AI 模型提供商
- pi-cache-optimizer：提升 Pi 在模型提供商侧的 KV Cache / Prompt Cache 命中率
- pi-web-access：为 Pi Agent 提供网页搜索、内容提取、视频理解等网络访问能力
- pi-permission-system：为 Pi Agent 提供集中的、确定性的权限管控
- @juicesharp/rpiv-todo：为模型提供一个可见的 Todo 任务列表，以编辑器上方的实时面板呈现

后面因为为了控制本地配置文件的读取，全部做了替换或者移除，现在没有使用任何外部插件，但是因为是使用ai参考上面插件做的替换，所以不排除ai会抄或者借鉴上面开源库的内容

#### doc和PDF导出
ai推荐了PDFKit和Pandoc，ai在对比了之后说好，就用了。
